# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Schwarzschild black hole as a floating macOS **widget**: Metal, one fullscreen triangle, one fragment shader. Every pixel near the hole numerically integrates its own null geodesic (Binet form, `a = -3/2 h² x/r⁵`); shadow, lensing, photon ring, accretion disk and time dilation all emerge from that integration rather than being painted on. Units: Schwarzschild radius `r_s = 1`.

Menu-bar-only (`.accessory` policy, `LSUIElement`), one `NSPanel` that lenses the live screen behind it via ScreenCaptureKit. See `README.md` for what it does; this file is for how not to break it.

`BlackHole.metal` is a hand port of `blackhole.glsl` from the Ghostty shader project it grew out of (MIT, s13k — see LICENSE). The two are **separate codebases now**: the GLSL keeps compile-time `const float` tunables, this one turned every tunable into a uniform. Nothing is shared and nothing needs to be kept in sync.

## Commands

```sh
swift run BlackHoleApp     # run it — the package has three executables now, so it needs the name
./make-signing-cert.sh     # once: stable identity so TCC grants survive rebuilds
./make-app.sh              # bundle dist/Black Hole.app
./make-icon.sh             # regenerate the icons from the renderer (rarely)
xcrun -sdk macosx metal -c Sources/BlackHoleApp/BlackHole.metal -o /tmp/bh.air   # syntax-check the shader
```

There is no linter, and `./make-check.sh` is what passes for a test suite: one contract check plus three offscreen measurements, each of the latter corresponding to a bug that actually shipped — the streak field winding itself below the pixel grid with uptime, a style clipping to white, and the lensed background aliasing. Run it after touching the shader. Verification here is measurement: render offscreen and count. Always run the bundled binary under `MTL_DEBUG_LAYER=1 MTL_SHADER_VALIDATION=1` after touching render targets — it has caught two bugs that were invisible in rendered frames.

## Targets

`BlackHoleCore` holds everything either side of the CPU→GPU seam has to agree on — the `Uniforms` struct, `Tunables`, `Specs`, `BackgroundFit`, and `FrameUniforms.make`, which is the only thing that fills a `Uniforms` in. Foundation only, so the two offscreen tools (`check-render`, `render-icon`) link it without dragging SwiftUI or AppKit behind them. That is the point of the split: the tools used to retype the uniform struct as a positional `[Float]` array each, which nothing checked.

`Params` in the app is the `ObservableObject` shell over a `Tunables`; the values themselves know nothing about publishing.

## The uniform struct

`struct Uniforms` in `BlackHole.metal` and `Sources/BlackHoleCore/Uniforms.swift` must stay identical. Both are all-`Float` on purpose — every member is 4-byte aligned, so declaration order *is* the memory layout. Append in groups of four, shrink the pads, never reorder.

This is no longer only a rule: `make-check.sh` reads the Swift declaration back with `Mirror`, parses the struct out of the shader, and compares them field for field. A reorder fails the check, which a size comparison could never catch.

Members are `public internal(set)`, so nothing outside `BlackHoleCore` can fill one in by hand. Half-filling a `Uniforms` at the call site is what put 37 fields in `Params` and the other 11 in `Renderer.draw`.

Ranges, groups, help text and defaults for each tunable live in `Sources/BlackHoleCore/Specs.swift`. A tunable with no spec still works but should get one. `check-render` measures every entry in `Specs.styles`, so a new style is covered without anyone having to remember it.

## Gotchas

- SwiftPM has **no `.metal` build rule** for an `executableTarget` (it reports the file as "unhandled"). `BlackHole.metal` ships as a `.copy` resource and `Renderer.makeLibrary` compiles it at launch; `BLACKHOLE_METAL=<path>` overrides the source for an edit-and-relaunch loop.
- `make-app.sh` must copy `BlackHoleApp_BlackHoleApp.bundle` into `Contents/Resources/` or `Bundle.module` can't find the shader at runtime.
- Textures load without sRGB decoding and the view uses `.bgra8Unorm` (not `*_srgb`): the shader composites in raw-sRGB space, which is what the terminal handed the original for free. Changing either end shifts the disk's tonemap.
- Metal's fragment `[[position]]` origin is top-left — the same top-down convention as Ghostty's `fragCoord`, so the y handling ported unchanged.
- MSL's `fmod` truncates where GLSL's `mod` floors; `gmod` in the shader exists for that, and `mirrorUV` plus the noise lattice wrap depend on it.
- **`MTLSamplerDescriptor.mipFilter` defaults to `.notMipmapped`**, and with it unset the sampler reads level 0 and nothing else — the mip chain the renderer rebuilds from the capture every frame and the derivatives `skySampleGrad` hands `gradient2d` are both silently ignored, and the lensed background aliases into crawling moiré. It must be `.linear`, *and* `maxAnisotropy` must be > 1: the footprint near the ring is compressed hard along one axis and barely along the other, so an isotropic mip picks the blur the worst axis needs and smears the halo (measured against a 4×-supersampled reference over a page of text, 0-255 luma RMSE: 13.5 point-sampled, 15.9 trilinear-isotropic — *worse* — 5.2 with anisotropy).
- Correct filtering stops the halo aliasing; it does not stop it being busy. A lens reproduces what is behind it, so over text the compressed annulus fills with legible lines a pixel apart. `BG_BLUR` adds LOD in proportion to the local compression (`extra = BG_BLUR · log2(g/g₀)`), which softens only the squeezed band and leaves the undistorted corners pixel-exact. A flat LOD bias would blur the whole widget instead.
- **The widget is round, the window is not.** The shader tapers its displacement radially (`PANEL_FADE_START/END`) and multiplies `skyAlpha` by the same factor, so the silhouette is a soft disc and the border band is not an opaque, capture-stale copy of the screen. `PanelController.silhouetteRadius` mirrors `PANEL_FADE_END`; the hit region and the resize rim are both defined against it. An NSWindow's click area is all-or-nothing, so the controller polls the pointer at 60 Hz and flips `ignoresMouseEvents` to match the disc.
- **Style fitting**: presets disagree about `DISK_OUTER` (7 r_s to 16), so the shader scales the hole down until the disk fits `PANEL_DISK_ROOM`. That is what lets one widget size hold every style without clipping.
- **The capture runs at one pixel per point, not at the display's backing scale** (`ScreenCapture.captureScale`). The extra resolution measurably goes nowhere: between the lens compression and `BG_BLUR`, the shader already samples around mip 1 across the whole visible disc, and the only genuinely 1:1 part of the widget is its outermost ring, which the silhouette taper has faded to nothing. A 2x capture against the same capture halved and blown back up, over a real screen (0-255 luma RMSE): 0.04 across the hole and disk, 0.38 through the warped halo, 0.55 in the near-1:1 band, 100% of the widget's detail retained. It buys a quarter of the pixels — at Large, 6.6 MB of texture plus its mip chain becomes 1.6 MB, and the per-frame blit and `generateMipmaps` shrink with it. Raising `BG_BLUR` toward 0 is the thing that would make the lost resolution start to matter.
- **ScreenCaptureKit does not go idle.** Measured on the running widget, it holds 29.5 fps (148 frames per 5 s against a `minimumFrameInterval` of 1/30) indefinitely, whether or not the captured region changes. A lensed background that looks frozen is therefore never the stream having stopped — look at what is actually behind the widget, and at how little the drift moves over it. `ScreenCapture.ingest` counts arrivals and logs only when five seconds pass with none.
- **ScreenCaptureKit**: the stream must exclude the widget's own window or it mirrors itself infinitely — `ScreenCapture` refuses to start rather than capture without the exclusion. It is bound to one display, so it restarts when the widget changes screens, and `Renderer` cross-checks `screen.displayID == frame.displayID` before sampling. `NSWindow.screen` is nil before a window is placed — resolve the widget's screen geometrically, never via `?? NSScreen.main`. On macOS 14+ the stream is cropped with `sourceRect` and re-aimed with `updateConfiguration` on a move; on 13 it captures the whole display and the shader indexes into it (`Frame.cropped`).
- **TCC and rebuilds**: an ad-hoc signature makes the designated requirement `cdhash H"…"`, so every rebuild revokes Screen Recording. `make-signing-cert.sh` creates a self-signed identity once (login keychain, `codeSigning` EKU, trusted for `codeSign`); `make-app.sh` auto-detects it and the requirement becomes `identifier … and certificate leaf = H"…"`, which survives rebuilds. Note LibreSSL is `/usr/bin/openssl` here and Security.framework rejects an empty-password PKCS#12 — the script uses a throwaway one. Capture failures back off 5 s and log once; an immediate retry loop hammers TCC.
- Capture and permission problems report to the unified log: `log stream --predicate 'subsystem == "dev.s13k.blackhole-app"'` (stderr is discarded for a bundled app).
- **`diskPhase`, not disk speed**: the shader gets an integrated rotation phase from the CPU. Flares and audio modulate the rate, and multiplying a large `time` by a changing factor jumps every streak at once (the GLSL warns about the same trap). Anything that varies the rate must go through the integrator in `Renderer.draw`.
- The flare drives **temperature over gain** (0.85 vs 0.55): the shipped styles already sit near the top of the tonemap, so extra gain clips the disk to a featureless white blob.
- Audio rides the existing `SCStream` as a second output type, so it needs the live-screen lens; there is no stream to listen through in "stars only".
- **Tonemapping is hue-preserving** (`tonemap()`): map the peak, carry the chroma, bleach only far past the knee. Per-channel `1-exp(-c)` was why the flare, the hot spot and every filament vanished into white — if something new "isn't visible", check this first.
- **Bloom's threshold has to sit above the disk, not inside it.** The disk's own body renders around 0.7, so a threshold of 0.55 put nearly all of it through the bright pass and it bloomed onto itself — every streak merged into one cream sheet. Measured on the running widget over a dark terminal (filament modulation, mean |∇²L| as a % of mean disk luma): 6.19 at 0.55/0.55, 8.62 at 0.35/0.85, 8.54 with bloom off entirely. The threshold wants to catch the inner edge and the photon ring only.
- **Bloom is a four-pass offscreen chain** (`BloomChain`), half-float, quarter-res. Two scene pipelines exist because a pipeline is only valid for the pixel format it was built against — the scene goes to `.bgra8Unorm` when bloom is off and `.rgba16Float` when it is on. Metal validation catches a mismatch; offscreen tests will not if they build their own pipeline. Always run `MTL_DEBUG_LAYER=1 MTL_SHADER_VALIDATION=1` against the bundled binary after touching render targets.
- **The disk and the background combine by addition, not by screen.** The tracer already multiplies the background by the disk's transmittance on the way through, so `base` is what actually escapes from behind and `glow` is what the gas emits — radiative transfer says those add. Screen is `base + glow − base·glow`, and that third term scales with the background's brightness, so it deletes the disk exactly where the background is brightest (measured over a real bright capture: disk-to-surround Michelson contrast 0.18 with screen, 0.22 with addition, surround unchanged). Screen had been reached for because plain addition clipped a pale wallpaper to paper; the fix for that is a *shoulder*, not a different operator — below a 0.90 knee the composite is exactly the identity, so where the disk contributes nothing the widget is still a pixel-exact window, and past it the sum rolls off to 1 hue-first. Occlusion is not the lever here: measured leak through the disk is already only 12-14% of its own light, and forcing `DISK_OPACITY` to 1 moves it by two points.
- **Nothing may clip to white**, and the render keeps finding new ways to. The tonemap maps intensity and carries chroma (bleach starts at peak 3, not 1.2) with an **extended Reinhard** shoulder — `1-exp(-peak)` hits 0.95 by peak 3, compressing every layer of the bright disk into the top few percent of the range; lowering `EXPOSURE` only dims it, since the fault is the curve's shape, not the image's placement on it; the disk is *screened* over the lensed background, not added; bloom is screened too **and fed a separate MRT emission target**, never the composed scene — keying it on the scene made a pale wallpaper glow. If something new "isn't visible", suspect saturation first.
- **The streak field winds itself to death** without `DISK_REFRESH`. `kep` falls off with radius, so the phase the gas has turned through is a function of radius, and multiplying it by a `diskPhase` that only ever grows shears the pattern into an ever-tighter spiral — the same reason galaxies cannot have material spiral arms. Measured fineness (mean |∇²L| as a % of mean disk luma) went 6.0 at launch, 15.4 after 30 s, 26.7 after 2 min, saturating near 33: every filament wound below the pixel grid and the disk became a sheet of noise. Symptom from the outside: "the ripples expand, then get denser and stop moving." The fix is the standard flow-noise one — two copies of the field wound half a period out of step, crossfaded so each is at zero weight the instant it restarts. Fineness then holds 7.5-10.4 from launch to 16 hours, and stepping across a restart changes the image 8.5 against 5.0-7.8 elsewhere, so there is no pop. Anything else that multiplies `diskPhase` by a radius-dependent rate needs the same treatment; the hot spot does not, because it lives at one radius.
- **The faller is drawn in front**, in screen space, not on the sky plane: the disk is opaque so a sky-plane object spends its descent hidden, and light from something falling in on the viewer's side is not lensed anyway. Its tearing is a Keplerian shear that is a pure function of radius, so the shader inverts it exactly rather than simulating particles. `Faller` and `Proximity` share the one sprite slot; a drop wins.
- **Double-dimming**: `Faller` must not apply the redshift fade — the shader does it per sample, which is what makes the debris go out in the order it reaches the horizon. Doing both once left the object at 14% opacity by the time it began to come apart, so the disruption happened where nobody could see it.
- **The plunging region** inside the ISCO is drawn (`PLUNGE`). Two traps: the crossing guard must reach below `DISK_INNER` (down to 1.02 r_s), *and* the Shakura–Sunyaev profile is exactly zero at `rin`, so `tprof` has to be evaluated at ≈1.36 `rin` for that region or widening the geometry changes nothing.
- **Never tint what is behind the widget.** The obvious answer to "the disk washes out over a bright wallpaper" is to dim the lensed background, and it is wrong: the widget composites its *own* copy of the screen at alpha 1, so dimming that copy does not dim the screen — it lays an opaque grey disc over it. It looks exactly like what it is. `BG_DIM` exists and defaults to 1 for this reason; anything automatic driving it turns the widget into a smoked-glass coaster. If the disk needs to win against a bright background, it has to be the disk that changes.
- **Reduce Motion / Low Power** are honoured via `SystemState`: the former zeroes `DRIFT` (the disk keeps turning — that is content, not motion), the latter caps the frame rate at 30 and scales `N_STEPS` by 0.6.
- **The widget parks itself** (`PanelController.syncRunning`) whenever nobody can see it: hidden with ⌥⌘B, displays asleep, session locked, or the window fully occluded. They all want the same thing — tear the stream down, `MTKView.isPaused`, stop the 60 Hz hit-test poll, disable `Proximity` — so they share one path, and only the explicit hide fades. Disabling `Proximity` is not optional: the render loop is what restores a cursor hidden inside the hole, so parking with the pointer inside would strand it. Stopping the poll also fixes a separate bug — it set `ignoresMouseEvents` purely from the pointer's position, so a hidden widget went on swallowing clicks where it used to be. Measured: 10.3% CPU visible, **0.0% parked**, and unparking has the stream back in ~130 ms, inside the 0.25 s fade.
- **The composition always fills the widget** (`PANEL_FADE_MAX`), so the window is the visible disc. `HALO` is the only proportion dial; `HOLE_FILL` and `DISK_ROOM` were removed because they algebraically cancel — all they changed was how much of the window went unused. The fit targets the *lit* extent `mix(rin, rout, 0.78)`, not `DISK_OUTER`.
- Dragging clamps to `screen.frame`, not `visibleFrame` — the latter stops at the menu bar and made the top of the screen unreachable.
- **The lensed halo has no motion of its own** — it is a static mapping of what is behind the widget. `DRIFT` (the GLSL's Lissajous, moved to the CPU) is what makes it move; without it the region outside the disk measures 0.25/255 of change per second, with it 13.5.
- The widget deliberately has **no size driver**: no context-window fill, no pomodoro, no roam box. Those exist only in `blackhole.glsl`.

## Inherited from the GLSL

- Metal's fragment `[[position]]` origin is top-left, which is the same top-down convention Ghostty's `fragCoord` used, so the y handling ported unchanged.
- MSL's `fmod` truncates where GLSL's `mod` floors; `gmod` exists for that, and `mirrorUV` plus the noise lattice wrap depend on it.

## Icons

`./make-icon.sh` regenerates `AppIcon.icns` and the menu-bar `MenuIcon.png` by running `swift run render-icon`, which drives `BlackHole.metal` offscreen through the same `FrameUniforms.make` the app uses. The icon's eight deliberate departures from Inferno are named in `iconTunables`. There is no icon art in the repo and there does not need to be — the thing the app draws is the thing the icon should be. Results are committed; only rerun it when the look changes. The app icon sits on a dark rounded plate because that is what a macOS icon is, and the composition is drawn *inside* the plate (overflowing it clipped the disk against the corner the roll throws it toward). The menu-bar image is the render's own luminance used as alpha, marked `isTemplate` so the system tints it for light and dark, shipped at 36 px and declared 18 pt.

## Performance

Profiled with `sample` on the running widget (Medium, 840x840, `N_STEPS` 48, 60 fps), the main thread is ~93% idle in `mach_msg`. Of the ~7% that is work, `Renderer.draw` is 276 samples in 4599 and **115 of those are blocked in `nextDrawable`** — vsync pacing, not cost. The hit-test and position timers do not appear at all. Two consequences: dropping the frame rate saves about a point of CPU (10.3% to 9.2% going 60 to 30) and the GPU difference is below the noise floor; and the 60 Hz pointer poll is not worth optimising, whatever it looks like on paper.

`N_STEPS` (geodesic integration steps per pixel) is the main GPU dial; only pixels inside the ray-traced circle around the hole pay it, and that circle scales with the hole — a large hole at high context fill on a high-DPI display is the worst case. `TOKEN_AREA_MAX` bounds how big it gets. In the app the widget is small enough that `N_STEPS` is the only dial that matters.
